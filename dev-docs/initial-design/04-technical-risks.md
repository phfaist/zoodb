# 04 — Technical risks to verify with a prototype

| id | risk | how to check |
|---|---|---|
| R1 | **Stack size in wasm.** flm-rs's recursion guard is a *budget* (48 MiB) that assumes a 64 MiB worker thread; wasm has no threads, so the binding must `mark_worker_thread` on the main thread and the wasm linear-memory stack must really be that large (wasm-bindgen's default is 1 MiB). Needs `-C link-arg=-zstack-size=<bytes>` (or `--stack-size`) at build, costing that much reserved memory in every page that loads the module; or a smaller configurable budget on the flm-rs side. | Try `GuardPolicy::DepthLimit(n)` (public; documented for tests because levels differ in stack use) calibrated against the wasm build with a margin, since a browser engine's native wasm call stack (about 1 MB) is the real limit and traps before a byte budget refuses; link a larger shadow stack only as far as needed. Upstream request U1 (agreed) makes the budget configurable; until it lands, `DepthLimit` calibrated against the wasm build. |
| R2 | **Binary size.** One FLM module serves every loading level (Q18): `flm-core` with stdcore and the ZooDb feature; `flm-core` has no per-backend cargo feature, only `parallel` (rayon), off for wasm. Base64 inlining as for the citation module (0.63 MB wasm → 0.84 MB JS) may be too heavy for the browser apps. | Measure `wasm-opt -Os` output; compare inlined vs fetched `.wasm`; check startup time in the browser. |
| R3 | **`flm-main` features on wasm.** CI checks `flm-main` without `fs` only; `graphics` (image, png, lopdf, roxmltree) and `citations` (hayagriva, autocitefetch, percent-encoding) are unverified on `wasm32-unknown-unknown`. | `cargo check --target wasm32-unknown-unknown --no-default-features --features graphics` (and `citations`). |
| R4 | **Synchronous services over asynchronous hosts.** Providers, resolvers and inspectors are called synchronously inside the run (as in the `flm` program, which fetches and reads files there). A wasm service can call JS synchronously but cannot await a Promise. Node has synchronous file reads but no synchronous HTTP; browsers have neither (sync XHR only in workers; `Atomics.wait` needs cross-origin isolation). | Per service, choose: synchronous host facility; a worker-thread relay (`Atomics.wait` / `receiveMessageOnPort`, as `synckit` does); or data gathered outside the run with a miss-then-fetch-then-rerun loop. Prototype the relay in Node and in a browser worker. |
| R5 | **Run cost at zoo scale.** One run per page (≈1000+ pages), one zoo-wide scan over ≈10–20k fragments, and, under Q12 (A), one run over every fragment the handbook renders (1155 codes today, several fields each), sequential in wasm. | Time a check run over a synthetic 20k-fragment document, an html run over a code-page-sized document, and a `latex-recomposed` run over a handbook-sized document, in Node and in a browser; watch linear-memory growth of the single large run. |
| R6 | **External index display content.** `ExternalTarget.display` is an `Arc<NodeTree<Flm>>`: the binding must build it from a parsed fragment handle (not from text). | Confirm the API to copy/borrow a fragment's tree into an index entry (`lang::copy`?). |
| R7 | **Recomposed LaTeX for the handbook (Q12).** Under (A), one run over the whole handbook: safe labels unique by construction, but duplicate labels across objects (3 in the EC zoo data today) are reported and written twice, so the data must be fixed and the scan must enforce uniqueness; the single `\flmRef{key}` hook carries raw object keys and safe labels alike, so the handbook's LaTeX dispatches on the key; the `[[` ligature and comment suppression. Under (B), safe labels restart per run and the handbook prefixes keys through the redefined `\flmLabels`/`\flmRef`, with one shared style file. | Prototype on a handful of codes with the handbook's class: raw object types, `drop_comments`, `style_file`/`style_stem`, the hook dispatch; compare with today's `subrecompose` output; then one full-size run for memory and time (R5). |
| R8 | **`srcset`.** Carried end to end in flm-rs (payload, emitter, published table, standard image rule) but the standard publish stage writes an empty list. | A ZooDb publish stage for `html` writes the published table (src by reference, srcset from pixel size and resolution) and is preferred over the standard stage. Verify: a feature may declare `.writes()` on a peer table owned by `graphics`, and the plan resolves the two writers by preference as it does for `compose` vs the final stage. | **Verified in milestone 2 (2026-10-16):** a host feature declares the published table as a peer table and a per-tree stage that writes it; the plan reports both writers (`flm.graphics.publish.html`, `zoodb.graphics.publish.html`) and refuses without a preference; with `Overrides::prefer` the ZooDb stage runs. **Blocked:** `GraphicsPublished` has no public constructor with content, so the stage cannot write what it computed; upstream request U2 (one `FromIterator` impl). The stage is complete behind the cargo feature `published-insert`.
| R9 | **MathJax 3 → 4 and the site CSS.** New HTML contract; the sites' SCSS and MathJax config must be rewritten; `tex-html` inside formulas. | Render one code page and diff visually. |
| R10 | **hayagriva vs citeproc-js** (only if Q6 = b). Known small differences (title casing). | Compare a sample of eczoo citation entries. |
| R11 | **Field positions in diagnostics.** Decided (Q15): the loader switches to the strict `yaml` package; 127 EC zoo files with quoted values continued at the key's column are re-indented once; flm-rs spans are byte offsets into the field's source and `FlmOrigin` has no base position, so the binding returns spans as byte offsets plus line and column within the field and the loader adds the field's start. | Write the re-indent script and the loader's message for the pattern; check the mapping inside literal, folded and plain scalars (`checks/yaml_compare.mjs`). |
| R12 | **Preview apps (zoodbtools).** `installZooFlmEnvironmentLinksAndGraphicsHandlers`, `CitationSourceApiPlaceholder`, `simpleRenderObjectWithFlm` live in packages not read here. | Inventory `@phfaist/zoodbtools_*` before fixing the API (Q18). |
| R13 | **Scan plan without retrieve.** Claim to verify: a plan request can demand `flm.citations.keys`, `flm.labels`, `flm.anchors`, `flm.refs.resolutions` and `flm.element-index` directly (`PlanRequest.demands: Vec<CapName>`; a table's name is a capability) so that a scan does not call the providers. | Build such a plan and check `stage_names()` excludes `flm.citations.retrieve`. |
| R14 | **Cost of installing a large external index per render run.** The EC zoo's index has thousands of entries (every object plus every zoo-wide label); it is installed on every per-unit run (`Externals::install_unstamped`). | Check whether `ExternalIndex` can be built once and shared cheaply (`Arc`) across runs, or whether each run takes a copy; measure with 10k entries. |
| R16 | **Two-pass composition (Q4.3).** Record pass, run, compose pass over `flm.output.html`. To verify: the record pass captures every placement in order, including from nested modules (`render_code_hierarchy_content`), and the equality check between passes gives a usable error; a one-command fragment `\ref{type:id}` parsed with layout `Inline` renders as a bare `<a>` through the external index; a plan can demand the per-tree table, `flm.output.html.pieces` and `flm.html.definitions` without scheduling the page's final stage; placed-tree segments (`HtmlSegment::Tree`) are spliced correctly by the host; the pieces selection (`PiecesRenderOptions`) is driven by what the composer placed. | Prototype on one `zoodb-example` page. |
| R17 | **Standalone-check stage (Q5).** The ZooDb feature declares an external table of standalone tree ids and a stage reading `flm.refpoints`, `flm.refs.resolutions` and the element index. | Verify: `SiteId` carries the node address (tree); an external table may be installed unstamped per run; a stage may read tables of three standard features; the diagnostic carries the field name through the tree's origin label. |
| R15 | **`\term{X}` across documents.** `defterm` declares the label types `term` and `topic`; a definition point gets a computed label from the term's identity and `\term` declares a reference site, so a term defined in one object and used in another must resolve through the external index like any label. | Test two documents: one with `\defterm{X}`, one with `\term{X}`, index built from the first's labels; check the computed label is what the index must carry. |
| R19 | **Data-level syntax compatibility.** The EC zoo data (≈1250 files) was written for the python FLM: its macros, environments, math delimiters, verbatim forms, float and note syntax, `\term`, `\cite` forms and the `quote` feature must parse under flm-rs's standard package with the same meaning, and content that no longer parses must be found before the port, not page by page. | Ruled 2026-10-15: no sweep of the EC zoo data now; the syntax is the same or nearly so, and agents fix discrepancies during the switch. The prototype (07) runs the two test data sets instead: both parse clean; one discrepancy found so far (`\\begin{itemize}[{⇒}]`, a custom bullet, refused by the lists feature). |
| R18 | **Fragment truncation for previews (Q13).** `truncate_to` cuts a fragment at about N characters at the node level; flm-rs has no such facility. | Verify that the binding can read the top-level node spans of a parsed fragment (and text node boundaries) so that a ZooDb helper computes a cut position in the source, appends the marker and parses the shortened source; compare the result with the old `_NodeListTruncator` on the EC zoo descriptions. |
