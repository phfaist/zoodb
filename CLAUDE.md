# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ZooDb is a JavaScript (ESM) library for building small in-memory databases ("Zoos") with relations and formatted content. It powers the [Error Correction Zoo](https://errorcorrectionzoo.org/). Data is stored in YAML files, validated against JSON Schema, and content is formatted using FLM (a LaTeX-like markup). Integrates with 11ty for static site generation.

Published as `@phfaist/zoodb` on npm.

HTML Documentation with API reference: in `doc/_build/html/index.html` and linked files.  HTML documentation is generated by calling `cd doc && poetry run make html`.

## Commands

- **Test:** `yarn test` (mocha)
- **Test with debug:** `yarn test-debug` (enables `DEBUG="zoodb*,mocha*"`)
- **Single test file:** `yarn mocha test/test_<name>.js`
- **Lint:** `yarn lint` (eslint on `src/**/*.js` and `tools/*.mjs`)
- **Build the wasm modules:** `yarn build:wasm` (runs `tools/build_wasm.mjs`: builds both crates of the `rust/` workspace with `wasm-pack` and regenerates `src/citationmanager/_wasm/` and `src/zooflm/_wasm/`); `yarn build:wasm citations` or `yarn build:wasm flm` builds one. The FLM build takes 1 to 3 minutes.
- **Rust checks:** one crate at a time, so that `serde_json/std` never reaches the citation crate through feature unification: `( cd rust && cargo clippy -p zoodb-autocitefetch-wasm --all-targets -- -D warnings && cargo test -p zoodb-autocitefetch-wasm && cargo clippy -p zoodb-flm-wasm --all-targets -- -D warnings && cargo test -p zoodb-flm-wasm )`

Toolchain prerequisites for the Rust bindings only (not needed to use or test the package, since the generated modules are committed): Rust stable, the `wasm32-unknown-unknown` target (`rustup target add wasm32-unknown-unknown`), `wasm-pack` (`cargo install wasm-pack`), and the local flm-rs checkout that `zoodb-flm-wasm` depends on by path (without it cargo cannot load the workspace at all).

## Architecture

**Core (`src/`):**
- `_zoodb.js` — `ZooDb` class: main database holding schemas, objects, and processors. Objects are keyed by `{object_type: {object_id: object}}`.
- `_zoodbloaderhandler.js` — `ZooDbDataLoaderHandler`: orchestrates loading/reloading data via data loaders, then validates.
- `schemaloader.js` — Loads and resolves JSON Schema definitions (with `$ref` support).

**DB Processors (`src/dbprocessor/`):** Pipeline of processors that transform data after loading. All extend `ZooDbProcessorBase` from `base.js`. Key processors:
- `relations.js` — Populates relation fields and backreferences between objects based on `_zoo_relations` schema annotations.
- `flmsimplecontent.js` — `FLMSimpleContentCompiler({ engine, error_policy })`: the field compiler; every `_flm` field (`full`, `standalone`, `block_level`, or `{ enabled, standalone, is_block_level }`) becomes a `ZooFlmFragment` of the engine in place, origin `{ object_type, object_id, field, source_path }` (label `source_path#field`; positions from `_zoodb.flm_field_positions[field]` when a loader records them); `_zoodb.flm_fields` lists the fields, `_zoodb.flm_diagnostics` holds the diagnostics; `'abort'` throws a `ZooFlmError` per object after all its fields are parsed. Dumps write the fragments' source.
- `flmprocessor.js` — `ZooFlmProcessor({ engine, contexts, refs, refs_defaults, graphics_address, citations, allow_unresolved_citations, error_policy, ... })`: over the engine, compiles the fields, runs one `engine.scan()` over the zoo (per object: labels with anchors and display sources, references, cited keys, images: `object_scan(type, id)`; duplicate labels and standalone violations are Errors on their objects), sets the index of every output context (objects, and labels with `#anchor` only when the label forms the anchor and their content as display only when it is standalone; `default` last), retrieves and compiles the citations (`CitationDatabaseManager`, `CitationCompiler`) into `engine.set_citations()`, collects the images (`ResourceCollector`) into `engine.set_graphics()`, fills the snippet cache; `compile_flm_fragment()` + `process_auxiliary_resources()` for ad hoc fragments; reloads re-process the zoo and release the replaced objects' fragments once that succeeded; `process_data_dump()` writes `data.zooflm` (`engine.dump()`; switch `flm_include_zooflm_data`).
- `searchabletext.js` / `searchabletextflm.js` — Generate searchable plain text; `FLMSearchableDocTextValuesAssembler({ engine })` renders the fragments' text through the engine (standalone ones from the snippet cache, the others in one `render_text` per object, each field's text rendered alone).
- `computeddata.js` — Compute derived data fields.
- `getgitlastmodified.js` — Attach git last-modified timestamps to objects.

**Data Loaders (`src/dbdataloader/`):**
- `yamldb.js` — `YamlDbDataLoader`: loads objects from YAML (or JSON) files on disk, validates against schemas. YAML through the `yaml` package, strict YAML 1.2 (core schema; `js-yaml` is gone); a parse error names file, line and column; a quoted value continued on a line not indented more than its key is refused with a message pointing to `zoodb-reindent-yaml`. `parse_file_data()` returns the plain data; `parse_file_data_with_positions()` (which calls it) returns `{ data, positions }`, and `parse_file_into_objects()` stores the positions of every string value in `obj._zoodb.flm_field_positions` (field path in the field compiler's dotted form, `relations.parents.0.detail` → `{ line, col, style, indent, approx }`; block scalars: the first content line, `col` = `indent + 1`; `approx` for folded, plain or quoted values spanning several lines and for one-line quoted values with an escape) when `load_objects` returns the file's data itself as the one object (the default). The engine's diagnostics then carry `file_line`/`file_col` (`(approx.)` in `format_diagnostic`).
- `flmfilesdb.js` — `FlmFilesDbDataLoader` (extends `YamlDbDataLoader`): `.flm` files with an optional YAML front matter and `\begin{field}{name} … \end{field}` blocks, read by the engine (`engine` in its config, required; the standard setup passes `zoodb.zoo_flm_engine`; `ZooFlmEngine.parse_fields(text, { origin })` over the core's `parse_fields`); stray content or an unclosed block throws a `ZooFlmError` with file positions; body fields get positions `{ line, col, style: 'field' }`. Only the environment name `field` is accepted.
- `_yamlparse.js` — internal: `parse_yaml_text()` (data and positions), `find_refused_quoted_scalar()` and `find_closing_quote()` (the refused pattern, shared with `tools/reindent_yaml.mjs`), `make_locator()`, `decode_text()`.

**ZooFLM (`src/zooflm/`):** FLM (Flexible LaTeX-like Markup) integration layer. Two layers side by side until step 5 of the redesign removes the old one (`dev-docs/initial-design/`). The old layer wraps the transpiled Python FLM library (in `flm-js-src/flm-js/`); package export `./zooflm`:
- `_environment.js` — Creates and configures FLM environments with zoo-specific features.
- `_fragmentrenderers.js` — HTML fragment renderers for FLM content.
- `scanner.js` — Scans FLM content for references, citations, resources.

Beside both layers, `citationcompiler.js` (package export `./zooflm/citationcompiler`) compiles citations (citeproc-js, CSL into FLM text, cached in `cache_compiled_citations.json`); it belongs to the new layer and imports nothing of the old one: `install_csl_flm_output_format({ parses })` takes the function that decides whether a text is valid FLM (`(text) => engine.parses(text)`), which the processor installs again before each compilation.

The new engine over the wasm core `ZooFlmCore` (package export `./zooflm/engine`; environment-neutral: these four files import nothing but each other and `_load_wasm.js`):
- `engine.js` — `ZooFlmEngine` (`ZooFlmEngine.create({ load_wasm, core, error_policy, unresolved, render_value_options })`): fragments over core handles, the index per context, the citations and graphics tables, `render_document` (the composer protocol), `render_fragment`, the snippet cache (`render_snippets`, `snippet`, `snippet_of_text`), `render_text`, `render_latex`, `scan` (per fragment the labels with anchors and display sources, the references as labels, the images; the cited keys; the duplicate labels), `truncate`, `html_definitions`/`html_stylesheet`/`html_scripts` (the script tags of the script definitions, MathJax 4 configured for FLM content, for a page's `<head>`), `parses`, `settings_hash` (the core configuration and the module's versions, `ZooFlmCore.version()`), `dump()`/`load(dump)` (the tables and the snippets for browser apps); re-exports the three modules below.
- `fragment.js` — `ZooFlmFragment` (source, origin with its canonical `label`, layout, standalone, handle, diagnostics, empty) and the origin helpers.
- `diagnostics.js` — the diagnostic shape, `format_diagnostic`, `ZooFlmError` (thrown under the `abort` policy), the policy helpers, byte offsets to lines and columns.
- `compose.js` — `ZooFlmComposition`: the composer helpers (`ne`, `rdr`, `rdrblock`, `ref`, `refhref`, `endnotes`, `piece`, `escape`), the markers `<flm:K:tree:N/>`, `<flm:K:piece:NAME/>`, `<flm:K:endnotes/>` (`K` a token per call) and their substitution.

**Standard Setup (`src/std/`):** High-level convenience layer. `stdzoodb.js` exports `makeStandardZooDb()` which wires up a ZooDb with common processors via config. Other `use_*.js` files are config helpers for individual processors: `use_flm_engine.js` builds the engine (`zoodb.zoo_flm_engine`) from `flm_options.load_wasm` (default the neutral loader; Node passes `load_zoodb_flm_wasm_node`), `flm_options.engine` (`dollar_math`, `settings`, `off`, `render_value_options`) and `allow_unresolved_references` (the srcset option is accepted but not enabled while upstream request U2 is open: images without `srcset`, one warning); `use_flm_processor.js` builds `ZooFlmProcessor` (context `default` from `zoo_permalinks.object`, image addresses from `zoo_permalinks.graphics_resource`, `make_citation_sources`); `continue_with_errors` sets the error policy (`'continue'`). The standard setup runs in browsers too: file access only through the config's `fs`, no `node:` import.

**Citation Manager (`src/citationmanager/`):** Manages bibliography/citation data. `_manager.js` (`CitationDatabaseManager`) adapts the wasm binding of the `autocitefetch` crate (retrieval, chaining, retry, TTL, cache); `_hostfetch.js` and `_cachefs.js` are the JavaScript host functions it uses for all I/O. Sources in `source/` (arXiv, DOI, manual, bibliography file) describe crate-native sources; other `CitationSourceBase` subclasses run as JavaScript sources via `run_retrieve_chunk()`. Cache files in `cache_dir`: `citations.jsonl` (written only by the crate), `cache_compiled_citations.json` (by `CitationCompiler`), throwaway `._citations*` (gitignored). The legacy `cache_downloaded_info.json` is no longer read. User docs: `doc/zoodb.citationmanager.rst`.

**Resource Collector (`src/resourcecollector/`):** Handles external resources (images, files) referenced by zoo objects: `ResourceCollector` (`collect(type, source)`, `get_resource_data()`), the file system retriever (`retriever/fs.js`: extensions tried, target name from a template), and `processor/flmgraphicsprocessor.js` (`FLMGraphicsResourceProcessor({ fs, global_vector_scale, global_raster_scale })`: inspects an image with `_inspectimagefile.js` and returns `{ graphics: { kind, media_type, width_px, height_px, dpi, width_pt, height_pt } }`, which the FLM processor completes into the engine's graphics table entries).

**Rust bindings (`rust/`):** A cargo workspace (`rust/Cargo.toml`, `resolver = "3"`; one `Cargo.lock`, `rust-toolchain.toml` and release profile, all committed; `rust/target/` gitignored) of two crates compiled to WebAssembly via `wasm-bindgen`. `zoodb-autocitefetch-wasm/` wraps the crates.io crate `autocitefetch`; all host I/O is delegated to JavaScript callbacks; never enable `serde_json/std` for it. `zoodb-flm-wasm/` wraps `flm-core` (path dependency on the local flm-rs checkout, read-only; where flm-rs is referenced from is settled later) with the ZooDb feature (`field` element, standalone check, `srcset` stage behind U2); class `ZooFlmCore` (typed in the generated `.d.ts`), driven by `src/zooflm/engine.js`; no I/O of its own; `build.rs` links a 64 MiB stack for wasm32 and reads the `flm-core` version from `Cargo.lock` (`ZooFlmCore.version()`). See `rust/README.md`, the crates' READMEs and `dev-docs/AutocitefetchImplementationPlan.md`.

**Generated wasm modules (`src/citationmanager/_wasm/`, `src/zooflm/_wasm/`):** Output of `yarn build:wasm` (wasm-bindgen glue, `.d.ts`, `BUILD_INFO.json`, and the binary: inlined as base64 for the citation module, the `.wasm` file itself for the FLM module), committed to git. **Do not edit by hand**; regenerate with `yarn build:wasm`. The citation module is loaded through the hand-written, environment-neutral `src/citationmanager/_load_wasm.js` (async, memoized). The FLM module has a loader pair: the environment-neutral `src/zooflm/_load_wasm.js` (`wasm_url`, `load_zoodb_flm_wasm(source)`: bytes, a `WebAssembly.Module`, a `Response` or a URL; without a source the browser fetches `wasm_url`) and the Node-only `src/zooflm/_load_wasm_node.js` (`load_zoodb_flm_wasm_node()`, reads the file); package exports `./zooflm/wasm` and `./zooflm/wasm-node`. The generated glue and the two neutral loaders may not reference `import.meta`, `require(`, `process.`, `Buffer`, `__dirname`, `node:` or `fs`, except the one `new URL('./_wasm/zoodb_flm_wasm_bg.wasm', import.meta.url)` in `src/zooflm/_load_wasm.js`.

**Tools (`tools/`):** Node-only ESM scripts (see `tools/README.md`): `build_wasm.mjs` (`yarn build:wasm`), `migrate_citations_cache.mjs` (package bin `zoodb-migrate-citations-cache --cache-dir <dir>`; converts a legacy `cache_downloaded_info.json` into `citations.jsonl`; `--help` for options), `extend_citations_ttl.mjs` (package bin `zoodb-extend-citations-ttl --cache-dir <dir> --prefix arxiv --add 60d`; shifts `stale_after`/`expires` of all `citations.jsonl` entries with the given cite prefix(es)), `merge_citations_cache.mjs` (package bin `zoodb-merge-citations-cache --cache-dir <dir> --from <file>`; merges another `citations.jsonl` into the cache, keeping for each id the copy that expires last), and `reindent_yaml.mjs` (package bin `zoodb-reindent-yaml <file-or-dir>... [--dry-run] [--indent N]`; re-indents the continuation lines of quoted YAML values indented no more than their key, which the strict loader refuses, touching nothing else, and verifies each file against a lenient reading of the original; imports the dependency `yaml`, so run it with `yarn node` in this repository).

**Utilities (`src/util/`):** Helpers for field access (`getfield.js`), HTML minification (`sqzhtml.js`), lexicographic sorting, etc.

## Key Patterns

- **ESM only** — all files use `import`/`export`, no CommonJS. Package type is `"module"`.
- **Debug logging** — uses the `debug` npm package. Namespaced as `zoodb.<module>`. Enable with `DEBUG=zoodb*`.
- **Processor pipeline** — ZooDb calls processors in order: `initialize_zoo()` → `process_zoo()`. On reload: `prepare_zoo_update_objects()` → `process_zoo_update_objects()`. Data dumps reverse the processor order.
- **Null-prototype objects** — database objects use `Object.create(null)` (no prototype) to avoid key collisions. Use `Object.hasOwn()` instead of `hasOwnProperty()`.
- **`_zoodb` metadata** — each stored object gets a `_zoodb` property with internal metadata (id, source path). This is excluded from schema validation.
- **FLM JS sources** — `flm-js-src/flm-js/` contains auto-generated JavaScript transpiled from Python FLM. Do not edit these files directly; regenerate from the [flm](https://github.com/phfaist/flm) repo. Do not attempt to read and understand these transpiled files.
- **Backup files** — files ending in `~` are editor backups; ignore them.
