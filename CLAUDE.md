# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ZooDb is a JavaScript (ESM) library for building small in-memory databases ("Zoos") with relations and formatted content. It powers the [Error Correction Zoo](https://errorcorrectionzoo.org/). Data is stored in YAML files, validated against JSON Schema, and content is formatted using FLM (a LaTeX-like markup), processed by flm-rs compiled to WebAssembly and bundled with the package. Integrates with 11ty for static site generation.

Published as `@phfaist/zoodb` on npm. Version 0.3.0 (unreleased), Node 20 or later (`engines`). The `files` list of `package.json` publishes `src/`, `tools/` and `README.md` only.

HTML Documentation with API reference: `cd doc && poetry run make html` builds it into `doc/_build/` (gitignored); open its `html/index.html`. The pages are Sphinx with `sphinx_js` (`doc/conf.py`, jsdoc configuration `doc/conf.json`): `js:autoclass` and `js:autofunction` directives pull the JSDoc of `src/`, so each one must name a module path and a symbol that exist.

## Commands

Yarn 4 with Plug'n'Play: run a script that imports the dependencies with `yarn node <script>`, not plain `node`.

- **Test:** `yarn test` (mocha)
- **Test with debug:** `yarn test-debug` (enables `DEBUG="zoodb*,mocha*"`)
- **Single test file:** `yarn mocha test/test_<name>.js`
- **Lint:** `yarn lint` (eslint on `src/**/*.js` and `tools/*.mjs`; no errors, and the CI test job runs it before the tests)
- **API sample:** `yarn node playground/play_example.mjs` loads the mini zoo of `test/test_data/flm_zoo/` through the standard setup and prints one rendered page and one text snippet (writes and fetches nothing)
- **Build the wasm modules:** `yarn build:wasm` (runs `tools/build_wasm.mjs`: builds both crates of the `rust/` workspace with `wasm-pack` and regenerates `src/citationmanager/_wasm/` and `src/zooflm/_wasm/`); `yarn build:wasm citations` or `yarn build:wasm flm` builds one. The FLM build takes 1 to 3 minutes. The tool passes `--remap-path-prefix` flags to rustc through `CARGO_ENCODED_RUSTFLAGS` (computed at each build, never committed) and fails if a build machine path (`/Users/`, `/home/`, `C:\`) is left in a binary, or if a cargo configuration file sets rustflags; the first build with the flags on a machine rebuilds everything.
- **Rust checks:** one crate at a time, so that `serde_json/std` never reaches the citation crate through feature unification: `( cd rust && cargo clippy -p zoodb-autocitefetch-wasm --all-targets -- -D warnings && cargo test -p zoodb-autocitefetch-wasm && cargo clippy -p zoodb-flm-wasm --all-targets -- -D warnings && cargo test -p zoodb-flm-wasm )`

Toolchain prerequisites for the Rust bindings only (not needed to use or test the package, since the generated modules are committed): Rust stable, the `wasm32-unknown-unknown` target (`rustup target add wasm32-unknown-unknown`), `wasm-pack` (`cargo install wasm-pack`), and network access the first time (cargo fetches flm-rs, the git dependency of `zoodb-flm-wasm`).

CI (`.github/workflows/node-js-test.yml`): the `test` job (Node 20 and 22: `yarn`, `yarn lint`, `yarn test`, then a build of the `zoodb-example` site, which fails against 0.3.0 until the example's port to the new FLM API reaches its default branch); the `rust` job (clippy and tests per crate, then both wasm-pack builds, build only).

## Architecture

**Core (`src/`):**
- `_zoodb.js` — `ZooDb` class: main database holding schemas, objects, and processors. Objects are keyed by `{object_type: {object_id: object}}`.
- `_zoodbloaderhandler.js` — `ZooDbDataLoaderHandler`: orchestrates loading/reloading data via data loaders, then validates.
- `schemaloader.js` — Loads and resolves JSON Schema definitions (with `$ref` support).

**DB Processors (`src/dbprocessor/`):** Pipeline of processors that transform data after loading. All extend `ZooDbProcessorBase` from `base.js`. Key processors:
- `relations.js` — Populates relation fields and backreferences between objects based on `_zoo_relations` schema annotations.
- `flmsimplecontent.js` — `FLMSimpleContentCompiler({ engine, error_policy })`: the field compiler; every `_flm` field (`full`, `standalone`, `block_level`, or `{ enabled, standalone, is_block_level }`) becomes a `ZooFlmFragment` of the engine in place, origin `{ object_type, object_id, field, source_path }` (label `source_path#field`; positions from `_zoodb.flm_field_positions[field]` when a loader records them); `_zoodb.flm_fields` lists the fields, `_zoodb.flm_diagnostics` holds the diagnostics; `'abort'` throws a `ZooFlmError` per object after all its fields are parsed. Dumps write the fragments' source. Works without a zoo (a browser app compiling a data dump's fields).
- `flmprocessor.js` — `ZooFlmProcessor({ engine, contexts, refs, refs_defaults, graphics_address, citations, allow_unresolved_citations, error_policy, ... })`: over the engine, compiles the fields, runs one `engine.scan()` over the zoo (per object: labels with anchors and display sources, references, images, term definitions with their bodies and `body_origin`, and every key each field cites with `cite_prefix`/`cite_key`: `object_scan(type, id)`; `scan_results`, whose `cited` keeps each key once with its first citation for the retrieval; duplicate labels and standalone violations are Errors on their objects), sets the index of every output context (objects, and labels with `#anchor` only when one of the labels of its point forms the anchor and their content as display only when it is standalone; `default` last), retrieves and compiles the citations (`CitationDatabaseManager`, `CitationCompiler`) into `engine.set_citations()`, collects the images (`ResourceCollector`) into `engine.set_graphics()`, fills the snippet cache; `compile_flm_fragment()` + `process_auxiliary_resources()` for ad hoc fragments; reloads re-process the zoo and release the replaced objects' fragments once that succeeded; `process_data_dump()` writes `data.zooflm` (`engine.dump()`; switch `flm_include_zooflm_data`).
- `searchabletext.js` / `searchabletextflm.js` — Generate searchable plain text; `FLMSearchableDocTextValuesAssembler({ engine, citations_in_place, pieces })` renders the fragments' text through the engine (standalone ones from the snippet cache, the others in one `render_text` per object, each field's text rendered alone; `citations_in_place`, default `true`: each citation shown as its entry, `[A. Author, …]`, through the per-call setting `citations.placement: 'in-place'`; `pieces` adds the footnotes, and the cited works when the marks are kept).
- `computeddata.js` — Compute derived data fields.
- `getgitlastmodified.js` — Attach git last-modified timestamps to objects.

**Data Loaders (`src/dbdataloader/`):**
- `yamldb.js` — `YamlDbDataLoader`: loads objects from YAML (or JSON) files on disk, validates against schemas. YAML through the `yaml` package, strict YAML 1.2 (core schema: dates stay strings, no `<<` merge keys); a parse error names file, line and column; a quoted value continued on a line not indented more than its key is refused with a message pointing to `zoodb-reindent-yaml`. `parse_file_data()` returns the plain data; `parse_file_data_with_positions()` (which calls it) returns `{ data, positions }`, and `parse_file_into_objects()` stores the positions of every string value in `obj._zoodb.flm_field_positions` (field path in the field compiler's dotted form, `relations.parents.0.detail` → `{ line, col, style, indent, approx }`; block scalars: the first content line, `col` = `indent + 1`; `approx` for folded, plain or quoted values spanning several lines and for one-line quoted values with an escape) when `load_objects` returns the file's data itself as the one object (the default). The engine's diagnostics then carry `file_line`/`file_col` (`(approx.)` in `format_diagnostic`). Data dumps keep the positions in `_zoodb`.
- `flmfilesdb.js` — `FlmFilesDbDataLoader` (extends `YamlDbDataLoader`): `.flm` files with an optional YAML front matter and `\begin{field}{name} … \end{field}` blocks, read by the engine (`engine` in its config, required; the standard setup passes `zoodb.zoo_flm_engine`; `ZooFlmEngine.parse_fields(text, { origin })` over the core's `parse_fields`); stray content or an unclosed block throws a `ZooFlmError` with file positions; body fields get positions `{ line, col, style: 'field' }`. Only the environment name `field` is accepted.
- `_yamlparse.js` — internal: `parse_yaml_text()` (data and positions), `find_refused_quoted_scalar()` and `find_closing_quote()` (the refused pattern, shared with `tools/reindent_yaml.mjs`), `make_locator()`, `decode_text()`.

**ZooFLM (`src/zooflm/`):** ZooDb's FLM layer, over the wasm core `ZooFlmCore` (the crate `rust/zoodb-flm-wasm/`, which wraps flm-rs's `flm-core`). Package exports: `./zooflm/engine` (`engine.js`; environment-neutral: `engine.js`, `fragment.js`, `diagnostics.js` and `compose.js` import nothing but each other and the default loader `_load_wasm_default.js`, whose browser variant the `browser` field of `package.json` selects in browser bundles), `./zooflm/citationcompiler`, and `./zooflm` (`index.js`, which re-exports both; browser code may import it). The wasm module and its loaders are internal (see the generated modules below): no package export, no exported name, and the engine hands out no core object.
- `engine.js` — `ZooFlmEngine` (`ZooFlmEngine.create({ core, error_policy, unresolved, render_value_options })`, which loads the module the first time, `core` the configuration as data `{ dollar_math, srcset, settings, off, link_target_blank }`; `link_target_blank`, default `true`: in the html output, `\href`/`\url`/`\email` to an address outside the site get `target="_blank"`): fragments over core handles (`make_fragment`, `release`), the index per context (`set_index`), the citations and graphics tables (`set_citations`, `set_graphics`, `tables`), `render_document` (the composer protocol), `render_fragment` (both, and `render_text`, `render_latex`, take `render_options`: values of the core's settings for that run only, `{ feature: { key } }` over the settings key by key; render-bound keys to the run, document-bound ones to its document, registry-bound ones (`citations.placement`, `citations.heading_title`, `xnotes.kinds`) make the run use a variant, a registry the core builds once per distinct set of such values and keeps with its plans, the run's fragments parsed again with its language; an unknown key or an unreadable value refused by name; e.g. `pieces.exclude` builds no endnotes, the marks stay), the snippet cache (`render_snippets`, `snippet`, `snippet_of_text`), `render_text`, `render_latex`, `scan` (per fragment the labels with anchors and display sources, the references as labels, the images, the term definitions `{ labels, anchor, display, body, body_start, body_end }`, the keys it cites; over all, the cited keys with their first citation; the duplicate labels), `truncate`, `parse_fields(text, { origin })` (the `\begin{field}{name} … \end{field}` blocks of an FLM file's body, `{ fields: [{ name, start, end, text }], diagnostics }`, for the FLM-files loader), `html_definitions`/`html_stylesheet`/`html_scripts` (the script tags of the script definitions, MathJax 4 configured for FLM content, for a page's `<head>`), `parses`, `settings_hash` (the core configuration and the core's version, `core_version`), `dump()`/`load(dump)` (the tables and the snippets for browser apps; `load` refuses another `settings_hash`); re-exports the three modules below.
- `fragment.js` — `ZooFlmFragment` (source, origin with its canonical `label`, layout, standalone, handle, diagnostics, empty) and the origin helpers (`range_origin`: the origin of a cut of a fragment's source, such as a term's body, with the file position moved to it).
- `diagnostics.js` — the diagnostic shape, `format_diagnostic`, `ZooFlmError` (thrown under the `abort` policy), the policy helpers, byte offsets to lines and columns.
- `compose.js` — `ZooFlmComposition`: the composer helpers (`ne`, `rdr`, `rdrblock`, `ref`, `refhref`, `endnotes`, `piece`, `escape`), the markers `<flm:K:tree:N/>`, `<flm:K:piece:NAME/>`, `<flm:K:endnotes/>` (`K` a token per call) and their substitution.
- `citationcompiler.js` — `CitationCompiler`: compiles citations (citeproc-js, CSL into FLM text, cached in `cache_compiled_citations.json`); `install_csl_flm_output_format({ parses })` takes the function that decides whether a text is valid FLM (`(text) => engine.parses(text)`), which the processor installs again before each compilation.

**Standard Setup (`src/std/`):** High-level convenience layer. `stdzoodb.js` exports `makeStandardZooDb()` which wires up a ZooDb with common processors via config (the engine first, then the relations populator, the git last-modified processor, the FLM processor, the searchable text processor, the `extra_db_processors`); `stdyamldbdataloader.js` exports `makeStandardYamlDbDataLoader()` (always passes `engine: zoodb.zoo_flm_engine` to the loader class); `index.js` re-exports `stdzoodb.js` and four of the `use_*.js` files. The `use_*.js` files are config helpers for individual processors: `use_flm_engine.js` builds the engine (`zoodb.zoo_flm_engine`) from `flm_options.engine` (`dollar_math`, `settings`, `off`, `link_target_blank`, `render_value_options`; any other key throws) and `allow_unresolved_references` (the srcset option is accepted but not enabled while upstream request U2 is open: images without `srcset`, one warning); `use_flm_processor.js` builds `ZooFlmProcessor` (context `default` from `zoo_permalinks.object`, image addresses from `zoo_permalinks.graphics_resource`, `make_citation_sources`; it always creates a citation manager, so a cite prefix without a source throws and a zoo that cites needs `citations.csl_style`); `use_searchable_text_processor.js` passes the engine to the assembler (`searchable_text_options.flm_citations_in_place`, `flm_pieces`); `continue_with_errors` sets the error policy (`'continue'`). The old entries `use_flm_environment` and `flm_options.environment_options` are refused with a message. The standard setup imports no `node:` module of its own (the engine's default loader reads the module's file under Node, and browser bundles get its browser variant): file access only through the config's `fs`.

**Citation Manager (`src/citationmanager/`):** Manages bibliography/citation data. `_manager.js` (`CitationDatabaseManager`) adapts the wasm binding of the `autocitefetch` crate (retrieval, chaining, retry, TTL, cache); `_hostfetch.js` and `_cachefs.js` are the JavaScript host functions it uses for all I/O. Sources in `source/` (arXiv, DOI, manual, bibliography file) describe crate-native sources; other `CitationSourceBase` subclasses run as JavaScript sources via `run_retrieve_chunk()`. Cache files in `cache_dir`: `citations.jsonl` (written only by the crate), `cache_compiled_citations.json` (by `CitationCompiler`), throwaway `._citations*` (gitignored). The legacy `cache_downloaded_info.json` is no longer read. User docs: `doc/zoodb.citationmanager.rst`.

**Resource Collector (`src/resourcecollector/`):** Handles external resources (images, files) referenced by zoo objects: `ResourceCollector` (`collect(type, source)`, `get_resource_data()`, `collected_resources`), the file system retriever (`retriever/fs.js`: extensions tried, target name from a template), and `processor/flmgraphicsprocessor.js` (`FLMGraphicsResourceProcessor({ fs, global_vector_scale, global_raster_scale })`: inspects a PNG, JPEG, TIFF or SVG file with `_inspectimagefile.js` and returns `{ graphics: { kind, media_type, width_px, height_px, dpi, width_pt, height_pt } }`, which the FLM processor completes into the engine's graphics table entries).

**Utilities (`src/util/`):** Helpers for field access (`getfield.js`), HTML minification (`sqzhtml.js`), lexicographic sorting, etc.

**Rust bindings (`rust/`):** A cargo workspace (`rust/Cargo.toml`, `resolver = "3"`; one `Cargo.lock`, `rust-toolchain.toml` and release profile, all committed; `rust/target/` gitignored) of two crates compiled to WebAssembly via `wasm-bindgen`. `zoodb-autocitefetch-wasm/` wraps the crates.io crate `autocitefetch`; all host I/O is delegated to JavaScript callbacks; never enable `serde_json/std` for it. `zoodb-flm-wasm/` wraps `flm-core` (git dependency on the branch `main-rs` of `https://github.com/phfaist/flm.git`, the commit pinned in `Cargo.lock`; `cargo update -p flm-core` moves it) with the ZooDb feature (`field` element, standalone check, `srcset` stage behind U2, the html rule of links in a new tab in `src/links.rs`); per-call registry-bound settings run on cached variant registries (`engine.rs`); class `ZooFlmCore` (typed in the generated `.d.ts`), driven by `src/zooflm/engine.js`; no I/O of its own; `build.rs` links a 64 MiB stack for wasm32 and reads the `flm-core` version from `Cargo.lock` (`ZooFlmCore.version()`). See `rust/README.md`, the crates' READMEs and `dev-docs/AutocitefetchImplementationPlan.md`.

**Generated wasm modules (`src/citationmanager/_wasm/`, `src/zooflm/_wasm/`):** Output of `yarn build:wasm` (wasm-bindgen glue, `.d.ts`, `BUILD_INFO.json` with `paths_remapped: true` and, for the FLM module, `flm_core_source` (the lock's source, with the commit for a git dependency; a module built from a path dependency has `"path"` and `flm_core_git: { commit, dirty }` instead), and the binary: inlined as base64 for the citation module, the `.wasm` file itself for the FLM module), committed to git. **Do not edit by hand**; regenerate with `yarn build:wasm`. Neither module nor any of its loaders is a package export: the loaders are internal. The citation module is loaded through the hand-written, environment-neutral `src/citationmanager/_load_wasm.js` (async, memoized). The FLM module has three loader files: the environment-neutral `src/zooflm/_load_wasm.js` (`wasm_url`, `instantiate_zoodb_flm_wasm(source)`: `source` required, bytes, a `WebAssembly.Module`, a `Response` or a URL; memoized, a failure forgotten), the default loader `src/zooflm/_load_wasm_default.js` (`load_zoodb_flm_wasm()`, which reads the file with `node:fs/promises`; what Node and any resolution ignoring the `browser` field load; the engine imports it), and its browser variant `src/zooflm/_load_wasm_default.browser.js` (`load_zoodb_flm_wasm()`, which instantiates from `wasm_url`, fetched by the glue, and rejects a `file:` URL), which the `browser` field of `package.json` (`"./src/zooflm/_load_wasm_default.js": "./src/zooflm/_load_wasm_default.browser.js"`) substitutes in browser bundles (Parcel 2 honors it with its default resolver and with `@phfaist/parcel-resolver-root`, as the EC zoo configures it; no `#…` subpath imports, which Parcel resolves only when the active resolver has package exports switched on). The two `_default` files export the same names. The generated glue, the two neutral loaders `src/citationmanager/_load_wasm.js` and `src/zooflm/_load_wasm.js`, and `src/zooflm/_load_wasm_default.browser.js` may not reference `import.meta`, `require(`, `process.`, `Buffer`, `__dirname`, `node:` or `fs`, except the one `new URL('./_wasm/zoodb_flm_wasm_bg.wasm', import.meta.url)` in `src/zooflm/_load_wasm.js`.

**Tools (`tools/`):** Node-only ESM scripts (see `tools/README.md`): `build_wasm.mjs` (`yarn build:wasm`; the path remapping and the binaries' path check, see Commands), `migrate_citations_cache.mjs` (package bin `zoodb-migrate-citations-cache --cache-dir <dir>`; converts a legacy `cache_downloaded_info.json` into `citations.jsonl`; `--help` for options), `extend_citations_ttl.mjs` (package bin `zoodb-extend-citations-ttl --cache-dir <dir> --prefix arxiv --add 60d`; shifts `stale_after`/`expires` of all `citations.jsonl` entries with the given cite prefix(es)), `merge_citations_cache.mjs` (package bin `zoodb-merge-citations-cache --cache-dir <dir> --from <file>`; merges another `citations.jsonl` into the cache, keeping for each id the copy that expires last), and `reindent_yaml.mjs` (package bin `zoodb-reindent-yaml <file-or-dir>... [--dry-run] [--indent N]`; re-indents the continuation lines of quoted YAML values indented no more than their key, which the strict loader refuses, touching nothing else, and verifies each file against a lenient reading of the original; imports the dependency `yaml`, so run it with `yarn node` in this repository).

**Other folders:** `playground/play_example.mjs` (the API sample, see Commands); `test/` (mocha tests; `test/test_data/` holds the fixtures, `flm_zoo/` the mini zoo of the FLM processor's tests); `doc/` (the Sphinx documentation); `dev-docs/` (design notes: `AutocitefetchImplementationPlan.md` for the citation crate, `initial-design/` for the FLM redesign around flm-rs, its status log in `initial-design/README.md`).

## Key Patterns

- **ESM only** — all files use `import`/`export`, no CommonJS. Package type is `"module"`.
- **Debug logging** — uses the `debug` npm package. Namespaced as `zoodb.<module>`. Enable with `DEBUG=zoodb*`.
- **Processor pipeline** — ZooDb calls processors in order: `initialize_zoo()` → `process_zoo()`. On reload: `prepare_zoo_update_objects()` → `process_zoo_update_objects()`. Data dumps reverse the processor order.
- **Null-prototype objects** — database objects use `Object.create(null)` (no prototype) to avoid key collisions. Use `Object.hasOwn()` instead of `hasOwnProperty()`.
- **`_zoodb` metadata** — each stored object gets a `_zoodb` property with internal metadata (id, source path, FLM fields, diagnostics, field positions). This is excluded from schema validation.
- **Diagnostics and the error policy** — FLM content never throws for what it holds: parses, scans and renders return diagnostics (`{ severity, identifier, message, origin, … }`, written by `format_diagnostic`). The error policy `'abort'` (the default) throws a `ZooFlmError` listing the Errors; `'continue'` (the standard setup's `continue_with_errors`) keeps them and renders the backend's recovery markup. Wrong arguments and released fragments throw a plain `Error`.
- **Backup files** — files ending in `~` are editor backups; ignore them.
